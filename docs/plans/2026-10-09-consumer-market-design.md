# 消費者食材市集（B2C）設計

2026-10-09 業主核准。實作計畫另見 `docs/plans/2026-10-09-consumer-market-plan.md`。

## 背景

業主希望一般消費者也能直接向平台上的供應商買食材；供應商在自己的後台上架商品。參考對象是可可商城 https://cocomart.com.tw/mp。

查過參考站：它是給**餐廳**用的「逛店＋詢價」目錄，商品不標價，也不能結帳、付款，FAQ 寫明「目前未提供交易功能」。所以這次只借它的版面與資訊架構，交易部分要自己做：
- 以店家為單位的賣場
- 先選「配送到哪」
- 每家店自訂配送區域與免運規則
- 購物車按店家分組

## 已定案的決定（2026-10-09）

| 題目 | 決定 |
|---|---|
| 消費者怎麼買 | 線上下單，由供應商自己收款（貨到付款／銀行轉帳），**平台不經手錢**。資料結構預留線上付款，之後不用重做 |
| 做在哪裡 | 產品站 `app.ifoodmap.ai/market`（沿用 Supabase、供應商後台、管理後台）；形象站加入口 |
| 商品審核 | 第一次開放零售要管理員核准才上架。改價格、庫存不用重審；改品名、照片、說明回到待審。管理員可隨時下架 |
| 消費者會員 | 不用註冊。填收件資料就能下單，用信裡的專屬連結查訂單 |

## 範圍

**這次做**
- 市集首頁、商品頁、店家頁
- 跨店購物車、免註冊結帳、訂單查詢頁
- 供應商：零售商品設定、店家設定、零售訂單管理
- 管理員：商品審核、零售訂單總覽
- 訂單狀態通知信

**這次不做（YAGNI，等確定有人買再加）**
- 線上刷卡、消費者帳號與登入
- 評價、優惠券、付費廣告版位
- 物流 API（黑貓等）、電子發票 API、平台抽成
- 商品規格變體：同一商品多種包裝，就上架成多個商品
- 搜尋引擎收錄（預渲染／SSR）

## 使用流程

### 消費者（`/market` 底下，未登入可用）

- `/market` 首頁：搜尋列、食材分類（沿用形象站 12 類與 `cat-*.svg` 圖示）、精選店家、商品列表。可以用配送縣市、溫層（常溫／冷藏／冷凍）篩選。
- `/market/p/:productId` 商品頁：
  - 照片（最多 5 張）、品名、零售規格、價格、溫層、產地、保存方式、保存期限、說明、庫存狀態
  - 店家卡：店名、配送縣市、運費、免運門檻、最低訂購金額、出貨天數
- `/market/s/:supplierId` 店家頁：logo、封面、介紹、退換貨說明、該店所有上架商品。
- `/market/cart` 購物車：存在瀏覽器 localStorage，按店家分組。每組顯示小計、運費（固定運費，達免運門檻免運）、是否達最低訂購金額。
- `/market/checkout` 結帳：
  - 填姓名、電話、Email、收件縣市與地址、備註
  - 每家店各選一種付款方式（只能從該店接受的方式裡選）
  - 勾選同意服務條款
  - 收件縣市不在某家店的配送範圍時，那家店不能結帳
  - 一次結帳，按店家拆成多張訂單
- `/market/orders/:token` 訂單查詢：不用登入。顯示每張訂單的狀態、明細、付款方式；選轉帳的，在店家接單後顯示匯款帳號。

### 供應商（現有 `/supplier` 後台）

- 商品管理（擴充 `SupplierCatalogPage`）：
  - 每項商品可以「開放消費者購買」，另填零售價、零售規格、庫存（可以不限）、溫層、產地、保存方式、保存期限、照片
  - 狀態顯示：草稿／待審／已上架／退回（含原因）
- 店家設定（新頁）：
  - logo、封面、介紹
  - 配送縣市、固定運費、免運門檻、最低訂購金額、出貨天數
  - 接受的付款方式、轉帳帳號、退換貨說明
- 零售訂單（新頁）：
  - 待接單清單
  - 可以接單、拒單（填原因）、標記已收款（轉帳）、出貨（填物流與單號）、完成、取消（填原因）

### 管理員（管理後台 build）

- 零售商品審核：待審清單，可以核准或退回（填原因），也可以下架已上架的商品。
- 零售店家：可以停用某家店的零售。
- 零售訂單總覽：唯讀，處理客訴用。

## 資料與流程

**另開零售專用的表**，不動餐廳的 `supplier_orders`／`order_events`。那套是詢價制：先下單、再報價，建單時 supplier_id 必須是 NULL，不適合零售。命名前綴 `market_`：

- `market_stores`（PK = supplier_id）：
  - 零售啟用（管理員可停用）、logo、封面、介紹
  - 配送縣市陣列、運費、免運門檻、最低訂購金額、出貨天數
  - 付款方式陣列（`cod`、`transfer`）、轉帳資訊、退換貨說明
- `market_products`：
  - supplier_id、可選的 supply_id（對應 B2B 商品，只供參考）
  - 品名、分類、零售規格、價格（TWD）、庫存（NULL = 不限）、溫層、產地、保存方式、保存期限、說明、照片路徑陣列
  - 審核狀態（draft／pending／approved／rejected）、退回原因、是否上架、審核者與時間
- `market_orders`：
  - 每家店一張，訂單編號
  - 收件人姓名、電話、Email、縣市、地址、備註
  - 小計、運費、總額、付款方式、狀態
  - 查詢 token 的 hash（只存 hash；同一次結帳的訂單共用一組 token）
  - 預留付款欄位：付款狀態、金流交易號，目前不用
- `market_order_items`：商品快照，包含品名、規格、單價、數量、小計。商品之後改價，舊訂單也不受影響。
- `market_order_events`：只能新增的狀態紀錄。比照餐廳訂單的做法：
  - 寫入前由 guard trigger 擋掉不合法的狀態轉換
  - 寫入後由 trigger 套用狀態、觸發通知

**訂單狀態**

```
pending（待接單）→ confirmed（已接單）→ shipped（已出貨）→ completed（完成）              ← 貨到付款
pending → confirmed → awaiting_payment（待付款）→ paid（已付款）→ shipped → completed    ← 銀行轉帳
pending → rejected（拒單，填原因）
pending / confirmed / awaiting_payment → cancelled（取消，填原因；供應商或管理員）
```

**下單 RPC `market_place_order`**（security definer，anon 可呼叫）：
- 伺服器重新查商品是否上架、價格、庫存，以及店家配送範圍、最低訂購金額、付款方式，**不相信瀏覽器送來的金額**
- 計算運費、扣庫存、建立訂單與明細，回傳 token
- 防灌單：比照 AI 框的 `ai_rate_take` 做法，限制同一網路、同一 Email 的下單次數；全部欄位都有長度上限

**查詢 RPC `market_get_orders(token)`**：用 token 換訂單內容。anon 不能直接讀 `market_orders`。

**權限（RLS）**
- anon：只能讀「已核准＋已上架＋店家零售啟用」的商品與店家資料
- 供應商：用 `current_supplier_ids()` 讀寫自家的商品、店家、訂單；狀態轉換只能走事件
- 管理員：全部

**商品照片**：新增 Supabase Storage bucket（公開讀取）。
- 路徑：`<supplier_id>/<product_id>/<檔名>`，storage RLS 只讓該供應商成員寫入
- 上傳前在瀏覽器壓成長邊 1600px 的 JPEG，沿用 `ReceiveOrderDialog` 的壓縮做法，但存成檔案、不存 base64
- 只收 jpeg／png／webp，每張 ≤ 2 MB

## 通知

- 寄給消費者：下單確認（含查詢連結）、接單或拒單、出貨（含單號）、取消。寄給供應商：新訂單。
- 新的 Edge Function `market-notify`，比照現有 `notify`：DB trigger 透過 pg_net 呼叫、共享密鑰驗證、Resend 寄出、寄信失敗不擋交易。
- **對真實消費者寄信要業主核准才開**：閘門 secret `MARKET_NOTIFY_LIVE`。沒開時，所有信轉寄到 ifoodmaptw@gmail.com，主旨加「[測試轉寄]」。

## 驗證方式

- 前端：vitest 測購物車分組、運費與免運、最低訂購金額、表單驗證、token 頁。
- 資料庫：正式庫 BEGIN…ROLLBACK 乾跑。這個專案沒有 staging，比照 AI 防濫用那次的做法。要驗：
  - 下單 RPC 改不了價格
  - 庫存不足、超出配送範圍、未達最低金額時被擋
  - anon 讀不到訂單
  - 不合法的狀態轉換被擋
  - 供應商讀不到別家資料
- 每個階段做完，派一個沒參與實作的 agent 獨立驗收。
- 上線前由業主實測一輪：測試店家上架 → 審核 → 消費者下單 → 供應商接單出貨。

## 分階段

1. **上架＋逛店**：DB（店家、商品、Storage）、供應商零售商品與店家設定、管理員審核、消費者首頁／商品頁／店家頁（還不能下單）
2. **購物車＋下單**：購物車、結帳、下單 RPC、訂單查詢頁、供應商零售訂單頁、管理員訂單總覽、通知信（測試轉寄模式）
3. **對外開放**：形象站入口、服務條款與隱私權政策頁、業主核准後打開 `MARKET_NOTIFY_LIVE`

## 業主待辦

- 確認有哪些供應商願意接小量零售單、願意自己出貨與收款
- 消費者服務條款與隱私權政策：我們先擬草稿，建議請法律專業確認。重點有三：
  - 平台是仲介，供應商是賣方
  - 生鮮與易腐食品依「通訊交易解除權合理例外情事適用準則」不適用七天鑑賞期
  - 發票由供應商開立
- **Supabase 升級 Pro**：免費方案閒置會暫停，消費者商店暫停等於關店
- 核准對真實消費者寄信（開 `MARKET_NOTIFY_LIVE`）
